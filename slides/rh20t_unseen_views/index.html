Data

RH20T, all 7 robot configs: 12,745 usable episodes, 2% held out by episode. Static cameras only, 320×160 per view.

Clip

13 frames at 3 fps (4 s) per view; cameras synchronised within 60 ms. Context cameras picked at random per sample.

Camera geometry

Every view gets a Plücker raymap from calibration, so the model knows where each camera is.

Setup2

Two arms, same starting point

Two models; one also gets a point-cloud input

1

Depth

Frame-0 sensor depth from the two context cameras (RH20T depth release).

2

Fuse

Unproject with calibration into one coloured world point cloud.

3

Render

Z-buffer splat into all four cameras; holes stay empty.

4

Encode

VAE latent (16 ch) + coverage mask (1 ch) into latent frame 0.

5

Condition

17 extra input channels, zero-initialised, so step 0 equals the RGB model.

Model with point cloud

Input: frame-0 RGB + camera raymaps + the rendered point cloud. Output: RGB video. 1 node × 4 H200, batch 4, grad. accumulation 2.

Model without point cloud (control)

Input: frame-0 RGB + camera raymaps. Output: RGB video. 2 nodes × 4 A100 80 GB, batch 4. Same data, steps and global batch.

Both: init from the 10k-step all-views baseline · 10,000 steps · lr 2e-5 · global batch 32 · ~9 h each. Both were then trained further (RGB to 32k, point cloud to 43k+).

How far to trust this

A real but modest gain, measured with image metrics only

One seed per arm

The confidence intervals cover clip-to-clip variation, not training-run variation. A second seed would show how much of +0.58 dB is luck.

PSNR rewards copying

Scenes barely move in 4 s, so copying frame 0 scores 26.1 dB on observed views. PSNR says little about whether motion or geometry is right.

No 3-D check yet

Nothing yet tests whether the generated views agree with each other in 3-D, which is what the point cloud should help most.

Not yet the project goal

The cloud is static (frame 0 only) and only fills in views. The agreed goal is a world model that takes point-cloud observations and predicts how the scene evolves.

Caveats9

Next steps

Better metrics, a sharper first frame, then a dynamic cloud

  • Metrics that see motion and 3-D: PSNR/LPIPS on moving pixels only, cross-view reprojection error with sensor depth, and FVD.
  • Sharper first frame: condition on more history frames and test more sampling steps, to close the 6 dB gap at frame 1.
  • Point-cloud history: feed clouds from several past frames, not only frame 0, as the conditioning observation.
  • Predict geometry: have the model output future depth or points, so the scene evolution itself is 3-D.
  • Second seed and render ablations: repeat the 10k comparison; drop the coverage mask; vary the number of context cameras.
